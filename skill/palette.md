# 配色 · 怎么从库里取

色值不在本技能里，在 `frontend-assets` 仓库的 `colors/` 下：

- `colors/data/neutrals.json` — 10 组中性色 × 11 档 = 110 色（5 组 Tailwind 官方值，5 组同阶梯推导）
- `colors/data/accents.json` — 14 个色相 × 4 档 = 56 色（base 已压饱和度 ≤62%）
- `colors/build.mjs` — 重新生成这两个文件
- `index.html` — 浏览器里点两个色块算 ΔL 与对比度

每个色值自带 `hex / rgb / hsl / lab` 和两个方向的对比度，不用自己算。

---

## 一、取一组色

```bash
cd skill
node pick-color.mjs --list                          # 看有哪些中性色和亮色
node pick-color.mjs --neutral stone --accent teal   # 出一套
```

输出三块：角色对照表（含对底对比度）、五项检查、可直接粘的 CSS 变量。

脚本按固定角色取档，不让你自由发挥：

| 角色 | 取哪档 | 干什么 |
|---|---|---|
| `--bg` | 50 | 底色 |
| `--surface` | 100 | 卡片面、分区底 |
| `--line` | 200 | 分隔线、边框 |
| `--ink-soft` | 600 | 次级文字、图注 |
| `--ink` | 800 | 正文 |
| `--ink-strong` | 900 | 强调文字、标题 |
| `--accent` | base | 小面积强调（≤8% 画面） |
| `--accent-tint` | tint | 大面积色块、选中行 |
| `--accent-deep` | deep | 彩色底上的文字 |

## 二、脚本替你验的五条

| 检查 | 门槛 |
|---|---|
| 正文 / 底 | ≥4.5:1 |
| 次级文字 / 底 | ≥4.5:1 |
| 亮色文字 / 底 | ≥3:1 |
| 主色与底 ΔL | 20–35 |
| 中性色饱和度 | ≤45% |

**ΔL 不合规时它会告诉你哪一档可用。** 多数亮色的 `base` 对近白底是 49–52，超出上限——这正是「对比克制」在起作用：base 只能做 ≤8% 的小面积强调，大面积要用 `light` 档。

## 三、五条硬规则（`RULES.md` 5.2 / 5.6）

1. 单画面 **≤5 色**
2. 每画面**一个明确主色**，主色可以是中性色本身
3. 对比**克制**，不出现高对比
4. 用亮色时总色数 **≤3**，亮色只承担「强调 / 突出主体 / 凸显个性」之一
5. 亮色面积 **≤8%**；大面积色块用 `tint`，不用 `base`

多色的唯一合法理由：同系列不同产品之间做区分。

## 四、手工挑选时的顺序

1. **先定气质，再定色**：木色极简、意式极简这类标签定的是气质，不是 hex
2. **先在中性色里选骨架**（暖灰 / 冷灰 / 米色 / 石墨），这一步定完页面已经有 80% 的样子
3. **最后加一个亮色**，只加一个，并想清它承担三职能中的哪一个
4. 不确定就去 `index.html` 点两个色块，看数字

## 五、常见错误

- 用 `base` 铺整块背景 → ΔL 直接爆表，画面变刺眼
- 彩色底上用灰字做次级文字 → 灰在彩色上会脏，要从该色相里调
- 一个页面出现两个亮色 → 除非是多产品并列，否则失控
- 中性色选了两组相近的（stone + neutral）→ 等于没有选择，只显得脏
