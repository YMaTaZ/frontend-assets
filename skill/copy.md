# 文案

界面上的字是控件的一部分，不是装饰。写文案的标准只有一条：**让人知道下一步做什么，以及出了事怎么办。**

---

## 一、四条总则

1. **说动作，不说功能**。按钮写「保存草稿」，不写「提交」
2. **说结果，不说过程**。「已保存到本地」比「正在执行保存操作」有用
3. **说清出路**。错误必须包含「出了什么问题 + 怎么解决」，两件都要
4. **用产品自己的词**。用户在别处看到的名词，这里必须一样

## 二、控件命名

| 别写 | 写 |
|---|---|
| 确定 / 提交 | 保存修改 / 删除 3 个文件 |
| 取消 | 先不删 / 返回编辑 |
| 是 / 否 | （不用是非题，把动作写进按钮） |
| 更多 | 更多设置 |
| 点击这里 | 下载 PDF |

**判断法**：把按钮上的字单独拿出来，不知道自己在哪个页面的人能不能看懂。看不懂就是没写清。

同一动作全站同一个词。这次叫「删除」，下次叫「移除」，用户会以为后果不同。

## 三、错误信息

三段式：**发生了什么 → 为什么 → 怎么办**。

```
✗ 操作失败
✓ 文件太大（18.4MB），上限 10MB。压缩后重试，或换一个文件。
```

- 不写「系统错误」「未知错误」「请联系管理员」——这三句等于没写
- 不把技术细节丢给用户：`ECONNREFUSED` 不是文案
- 不 blame：不写「您输入有误」，写「邮箱缺少 @ 号」
- 表单错误就近显示，同时在提交按钮旁给一句总述

## 四、空态

三件套，缺一件就是没做完：

1. **这里会有什么**：「还没有项目」
2. **为什么重要**：「项目用来放同一件事的所有文件」
3. **怎么开始**：一个主按钮 + 一句操作说明

```
还没有项目
项目把同一件事的文件和对话放在一起。
[新建第一个项目]  约 30 秒
```

空态禁止卖萌。不写「空空如也呢～」，也不用插画填满整屏。

## 五、加载与等待

| 时长 | 写法 |
|---|---|
| <400ms | 不显示加载态，避免闪烁 |
| 400ms–2s | 骨架屏或 inline spinner，**不写文字** |
| >2s | 写清在做什么：「正在解析 12 个文件（3/12）」 |

超过 10 秒要给「可以先去别处」的出口。进度不确定就用「大约还需 20 秒」，不要用会打脸的百分比。

## 六、成功反馈

- **小操作**：就地变化，不弹窗不 toast
- **破坏性操作**：一句确认 + 撤销入口（「已删除 3 个文件 · 撤销」）
- **不可撤销的长任务**：给结果链接，不只说「完成」

不写「操作成功」。成功要有具体内容。

## 七、语气

- 中文用「你」，不用「您」也不用「亲」
- 不感叹号。一句一个都不加
- 不用「请」开头的祈使句堆礼貌：「请点击下方按钮进行保存」→「保存」
- 一句话一件事，超过 25 字就换行或删

## 八、检查

- [ ] 按钮都在说动作，没有「确定 / 提交」
- [ ] 每个错误都说清了问题与出路
- [ ] 空态有三件套
- [ ] 没有「系统错误」这类废话
- [ ] 同一动作全站一个词
- [ ] 没有感叹号
- [ ] 长文案没有超过两行的
