## 1. 设计原则

### 1.1 核心命题 【定】

**低摩擦是唯一目标。**

用户完成一件事所需的步骤越少、犹豫越少、出错后的代价越小，设计越好。
视觉极简只是达成低摩擦的手段之一，不是目的。

由此推出全篇最重要的一句：

> **Simplicity 不等于 Minimalism。**
> 简洁不是把元素删到最少，而是消除摩擦。
> 有时候增加一点上下文提示，反而让界面在认知上更简单。

判断标准永远是「完成一件事要几步」，不是「画面上有几个元素」。

### 1.2 三大主旨 【定】

来自 Apple HIG。每条都转成可检查的动作：

| 主旨 | 含义 | 怎么检查 |
|---|---|---|
| **Clarity 清晰** | 每个元素都有明确用途，不需说明书就能懂 | 遮住文案，还能猜出这个区块是干什么的吗 |
| **Deference 退让** | 界面不与内容竞争 | 页面上的控件视觉重量是否 ≤15% |
| **Depth 层次** | 视觉层与动作传达层级关系 | 用户能否说出「现在在哪一层」 |

### 1.3 八原则 【定】

来自 WWDC26《Principles of great design》。每条配一个可执行检查。

| 原则 | 含义 | 怎么检查 |
|---|---|---|
| **Purpose 目的** | 每个功能都在索取时间与信任；决定不做什么比做什么更重要 | 这一屏里，去掉哪一块用户会真的察觉不到 |
| **Agency 主体性** | 不挡路、给探索自由、**能从错误里恢复** | 误操作后能不能一步撤回 |
| **Responsibility 责任** | 以用户最佳利益行事，从隐私开始 | 有没有为了好看而牺牲可读性或安全 |
| **Familiarity 熟悉感** | 该不该用废弃物隐喻 | 有没有发明没人见过的新交互 |
| **Consistency 一致性** | 同一逻辑稳定复现，用户能预测 | 同样的控件在两处行为是否一致 |
| **Flexibility 灵活性** | 为不同能力的人留余地 | 缩放到 200%、关掉动效后还能用吗 |
| **Simplicity 简洁** | 消除摩擦，不是删元素 | 完成核心任务要点几下 |
| **Craft 工艺** | 排版、动画、性能的长期打磨 | 有没有 1px 的对不齐、半帧的卡顿 |
| **Delight 愉悦** | 前面都做对后的自然结果，不是撒彩纸 | 愉悦来自哪里；如果答案是「有个动画」，就是错 |

### 1.4 撤销优先于确认 【定】

来自 Agency 原则的落地规定：

- 误操作靠 **Undo** 解决，不靠弹窗打断
- 只有**不可逆**的破坏性操作（删除账号、清空数据）才用阻断式确认
- 把纠错成本交给系统，不要把防范成本转嫁给用户

### 1.5 愉悦的来源 【定】

禁止靠彩纸、粒子、弹跳制造愉悦。愉悦只能来自：目的达成、路径顺畅、工艺扎实。

## 2. 控件与内容分离 【定】

来自 Liquid Glass 的行为规则，材质本身不搬，行为规则搬。

### 2.1 层结构

页面只有两层：

| 层 | 装什么 | 允许的视觉手段 |
|---|---|---|
| **控件层** | 导航、标签栏、浮动按钮、浮层、工具条 | 半透明、模糊、描边、浮起阴影 |
| **内容层** | 正文、图片、卡片、列表、表格 | 纯色、纸纹、留白；**不加玻璃** |

**铁律**：模糊与半透明只允许出现在控件层。内容区永远干净——不许玻璃列表、玻璃卡片、玻璃表格单元格。

### 2.2 三条行为

- **控件浮在内容之上**，是独立功能层，不是内容的一部分
- **控件退让**：滚动时导航收缩、变淡、可隐藏；回滚时展开。不做常驻动画
- **底图亮时的暗化**：控件若浮在明亮图片上，加 35% 暗化层保证可读

### 2.3 特效预算

所有特效（模糊、阴影、渐变、纹理）加起来，**面积不超过画面 15%**。

## 3. 两种模式 【定】

同一套 token，两种驱动方式。

| | `page` 网页 | `slide` 幻灯片 |
|---|---|---|
| 画布 | 流式，随视口伸缩 | 固定 1280×720，等比缩放 |
| 动效触发 | 滚动进入视口 | 翻页时入场 |
| 字号基准 | 16px | ×1.4 倍率 【默认】 |
| 导航 | 滚动 + 锚点 | ← → 翻页、键盘、进度 |
| 溢出 | 页面变长 | 必须一屏装下 |
| 导出 | 不需要 | 打印成 PDF，`@page` 横向 |

**硬约束**：`slide` 模式禁用一切滚动触发组件。`FadeContent`、`ScrollReveal`、`ScrollFloat`、`ScrollVelocity` 在幻灯片里不会触发，改用翻页驱动。

## 4. 配色

### 4.1 纲领 【定】

**不锁色值，锁原则。** 风格标签（木色极简、意式极简）只定气质，不预设 hex。

色值来自 `frontend-assets` 仓库，技能只引用，不内置。

### 4.2 五条硬规则 【定】

1. 单画面 **≤5 色**
2. 每个画面有**一个明确主色**（主色可以是中性色本身）
3. 对比**克制**，不出现高对比
4. 留白充足（见 5.3）
5. 用亮色时总色数 **≤3**，且亮色只承担三种职能之一：强调功能 / 突出主体 / 凸显个性

### 4.3 多色的唯一合法理由 【定】

同系列不同产品之间做区分。除此之外，多色就是失控。

### 4.4 底子 【参考，不强制】

三组方向，从库里挑，不钉死：

| 方向 | 库里对应 |
|---|---|
| 灰系中性（暖灰 / 冷灰 / 石灰色 / 灰褐） | `stone` `neutral` `zinc` `gray` `slate` |
| 米色与大地（米白 / 燕麦 / 沙色 / 浅咖 / 灰褐） | `ivory` `oat` `sand` `clay` `taupe` |
| 黑白灰 | `neutral` 两端 |

### 4.5 可测阈值 【默认】

- 中性色饱和度：HSL **S ≤ 45%**
- 主色与底色明度差（Lab ΔL）：**20–35**；超过 50 算高对比，不合规

### 4.6 亮色 【定】

- 只做强调、主体、个性三件事之一
- 单画面最多 1 个亮色色相，最多用它的 2 个档
- 大面积色块不得用亮色，亮色面积 **≤8%** 画面

## 5. 字体 / 间距 / 版面

### 5.1 字体策略 【定】

**零网络字体。** 不打包、不子集化、不上传任何字体文件。

字体只通过 `font-family` 栈引用：本机装了就用，别人打开自动回落系统字体。

四个原因同时成立：

1. 中文一个字重 3–10MB，网页加载不可接受
2. MiSans、鸿蒙 Sans 等免费商用字体明确禁止「单独再分发」
3. 子集化在法律上等于「修改」，而这些字体禁止修改
4. 导出 PDF / 卡片 CSP 都会拦外链字体

**后果**：验收必须按**回落后的效果**算，不能只按本机装了字体的效果算。

### 5.1.1 三条字体栈 【定】

```css
--font-display: "Google Sans", "Myriad Pro", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
--font-body:    "MiSans", "HarmonyOS Sans SC", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", system-ui, sans-serif;
--font-mono:    "DejaVuSansM Nerd Font Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace;
```

完整清单与许可记录见 `skill/fonts.json`；字体文件在本地 `F:\OH-WorkSpace\fonts-src\`，不进仓库。

### 5.1.2 禁用清单 【定】

- ❌ 把苹方、微软雅黑的字体文件打包进任何仓库
- ❌ 把商业字体（Google Sans、Myriad Pro、Eras、Avant Garde、Neo Sans Pro、Sackers Gothic、DIN 1451）打包或子集化
- ❌ 用 `@font-face` 指向任何未经授权确认的字体文件
- ✅ 只在 `font-family` 栈里写字体名做回落——不复制、不传播，风险最低

### 5.1.3 字重 【定】

只用 **400 / 500**，中文没有 350 / 450 这种中间值。

深底浅字时：字重 400，靠行高 1.8 + 字距 +0.012em 补偿；若仍发虚，直接跳 500，不要停在中间。

层级靠字号、颜色、间距，不靠加粗。不用 Inter 当默认。

### 5.2 字号与阅读度量 【定】

三档体系，按信息密度调用，共用一套底层刻度：

| 档 | 阶梯（rem） | 用在 |
|---|---|---|
| **A 精简三档** | 1.75 / 1.25 / 1.0 | 落地页、单一信息页、幻灯片封面 |
| **B 四档带过渡**（默认） | 1.75 / 1.5 / 1.25 / 1.0 | 项目详情、作品集内页、长文档、幻灯片内容页 |
| **C 苹果式双档** | 2.125 / 1.0625 | 幻灯片章节页、数据大字、全屏主张 |

- **一屏只用一套**，不许混搭
- 正文不小于 16px（C 档 17px）
- 行宽 `--measure: 32em`（中文约 32 字，英文约 64 字符）
- 元信息固定 0.8125rem（13px），不参与档位变化
- 行高随行宽反向调；深底浅字三轴补偿
- 幻灯片：封面 A / 章节页 C / 内容页 B

完整取值、行高与检查清单见 `skill/typography.md`，可直接引用的变量在 `skill/tokens.css`。

### 5.3 留白 【定】

不用百分比。用**比值**：

- **区块之间的留白 ≥ 区块内部间距的 4 倍**（例：区块间距 96px，卡片内边距 24px）
- 幻灯片：页边距 ≥ 内容间距的 **3 倍**
- 段落之间用间距或首行缩进二者之一，不同时用

### 5.4 间距阶梯 【定】

**4 为基单位**：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96`

| 用途 | 值 |
|---|---|
| 版心 | 780–820px |
| 正文内边距（桌面） | 40–54px |
| 幻灯片安全边距 | 64px 【默认】 |

分组靠邻近，不靠加容器；节奏来自 tight 与 generous 的对比，不要一个值铺满全页。

### 5.5 同心圆角 【定】

嵌套元素共享圆心，圆角随层级递减：

| 层级 | 圆角 |
|---|---|
| 外层容器 / 卡片 | 12px |
| 内层区块 | 8px |
| 控件 / 按钮 | 6px |

**禁止全站一个圆角值。**

### 5.6 版面结构 【定】

- **眯眼测试**：虚化细节后仍能分出主、次、组，否则层级失败
- 禁止三栏等高功能卡
- 重复的卡片 / 分栏必须真的等价，否则是框架默认
- 响应式是**结构性重排**，不是等比缩小
- 触控目标可用，即使视觉标记很小

## 6. 动效

### 6.1 时长表 【定】

| 时长 | 用途 |
|---|---|
| 100–150ms | 即时反馈（按下、hover） |
| 150–300ms | 常规状态切换 |
| 300–500ms | 布局、浮层、视图切换 |
| 500–800ms | 焦点入场 |

**出场比入场快。**

### 6.2 缓动 【定】

`cubic-bezier(0.16, 1, 0.3, 1)`，不反射性上 bounce / elastic。

### 6.3 节流 【定】

- **只给一个焦点时刻**
- **同屏同时只让一个东西动** 【默认：1 个序列】
- 不做常驻动画；只在状态变化时动
- 控件退让（滚动收缩）算状态变化，不算常驻动画

### 6.4 强度 【默认】

`MOTION_INTENSITY = 2/10`。`taste-skill` 基线是 6，对极简是对冲的，必须覆盖。

### 6.5 技术约束 【定】

- 默认状态内容必须可见，脚本挂了不能白屏
- 不动 `width / height / top / left / margin`，用 transform 或 FLIP
- 模糊、滤镜、阴影、canvas、shader 限制在局部
- `will-change` 只在动画期间加
- `prefers-reduced-motion` 留替代路径：减少位移，保留状态变化，不是全关

## 8. 反例清单

出现任何一条，视为不合格：

- AI 紫渐变、深色 mesh 居中的 hero
- 三张一模一样的功能卡横排
- **玻璃拟态用在内容上**（玻璃卡片、玻璃列表、玻璃表格）
- 每屏都做滚动揭示、无休止微动效
- Inter + slate-900 组合
- 渐变按钮、重阴影（超过 `rgba(0,0,0,.04)`）
- 纯黑 `#000` / 纯白 `#fff` 大面积使用
- 多个强调色同时出现
- 字重 >500、边框 >2px
- 冷灰文字 `#666` `#888` `#999`
- 假名字（John Doe）、Lucide 用户图标当头像
- 每段都加图标、每个区块都套卡片
- 全站一个圆角值
- 用彩纸、粒子、弹跳制造「愉悦」
- 为了好看牺牲可读性（Responsibility 违背）
