## 1. 设计原则

### 1.1 核心命题 【定】

**低摩擦是唯一目标。**

用户完成一件事所需的步骤越少、犹豫越少、出错后的代价越小，设计越好。
视觉极简只是达成低摩擦的手段之一，不是目的。

由此推出全篇最重要的一句：

> **Simplicity 不等于 Minimalism。**
> 简洁不是把元素删到最少，而是消除摩擦。
> 有时候增加一点上下文提示，反而让界面在认知上更简单。

判断标准永远是「完成一件事要几步」，不是「画面上有几个元素」。

### 1.2 三大主旨 【定】

来自 Apple HIG。每条都转成可检查的动作：

| 主旨 | 含义 | 怎么检查 |
|---|---|---|
| **Clarity 清晰** | 每个元素都有明确用途，不需说明书就能懂 | 遮住文案，还能猜出这个区块是干什么的吗 |
| **Deference 退让** | 界面不与内容竞争 | 页面上的控件视觉重量是否 ≤15% |
| **Depth 层次** | 视觉层与动作传达层级关系 | 用户能否说出「现在在哪一层」 |

### 1.3 八原则 【定】

来自 WWDC26《Principles of great design》。每条配一个可执行检查。

| 原则 | 含义 | 怎么检查 |
|---|---|---|
| **Purpose 目的** | 每个功能都在索取时间与信任；决定不做什么比做什么更重要 | 这一屏里，去掉哪一块用户会真的察觉不到 |
| **Agency 主体性** | 不挡路、给探索自由、**能从错误里恢复** | 误操作后能不能一步撤回 |
| **Responsibility 责任** | 以用户最佳利益行事，从隐私开始 | 有没有为了好看而牺牲可读性或安全 |
| **Familiarity 熟悉感** | 该不该用废弃物隐喻 | 有没有发明没人见过的新交互 |
| **Consistency 一致性** | 同一逻辑稳定复现，用户能预测 | 同样的控件在两处行为是否一致 |
| **Flexibility 灵活性** | 为不同能力的人留余地 | 缩放到 200%、关掉动效后还能用吗 |
| **Simplicity 简洁** | 消除摩擦，不是删元素 | 完成核心任务要点几下 |
| **Craft 工艺** | 排版、动画、性能的长期打磨 | 有没有 1px 的对不齐、半帧的卡顿 |
| **Delight 愉悦** | 前面都做对后的自然结果，不是撒彩纸 | 愉悦来自哪里；如果答案是「有个动画」，就是错 |

### 1.4 撤销优先于确认 【定】

来自 Agency 原则的落地规定：

- 误操作靠 **Undo** 解决，不靠弹窗打断
- 只有**不可逆**的破坏性操作（删除账号、清空数据）才用阻断式确认
- 把纠错成本交给系统，不要把防范成本转嫁给用户

### 1.5 愉悦的来源 【定】

禁止靠彩纸、粒子、弹跳制造愉悦。愉悦只能来自：目的达成、路径顺畅、工艺扎实。

### 1.6 每条规则必须可验 【定】

写不出验收方式的规则不是规则，是抒情。

- 每条准则后面要么跟着一个可测值（px / ms / 比值 / 对比度），要么跟着一句「怎么看出来的」
- 写完一页必须**看一眼成品**再下结论，不看就改等于没改
- 验收要**成批做**：一次看全，把这一眼能看出的问题一次修完，不要微调一次截一次图

## 2. 产出流程 【定】

**顺序固定：大纲 → 动效主张 → 等分 → 空间主张 → 按块分配 → 实现 → 破格。不许跳步。**

四道门禁分别卡在大纲（一）、动效主张（二）、空间主张（三）、破格（四）之后。

**开工前先把第 9 节（浏览器表面）与第 10 节（反例清单）看一遍。** 前者是动笔时就要写进去的，不是事后补；后者是限制，不是收尾检查。

### 2.1 大纲：动笔之前

产出是一份结构化大纲，不是文案终稿。每个区块写三行：

- **主张**：一句话说完
- **支撑**：1–3 条
- **素材**：文字 / 图 / 数据 / 代码

另标优先级：**主 / 次 / 辅**。

**门禁一**：大纲没定，不碰任何视觉决定。不选色、不排版、不写 CSS。

**理由**：先排版后凑内容，等分会被内容撞碎；先定大纲，块数才有推导依据。

### 2.2 动效主张：与大纲同步（门禁二）

四行，**没有一行依赖块数**，所以跟大纲一起写。页面做出来之后可以修，但不能空着开工。

- **焦点时刻**：整页唯一一个值得被记住的动作序列，一句话说清它从什么到什么（「有个淡入」不算）
- **连续性**：哪些跳转 / 布局变化需要被解释，用什么（共享元素 / FLIP / 视图过渡）；无则写「无」
- **反馈**：哪些控件与结果需要被确认，多快（100–150ms）；无则写「无」
- **预算**：哪个效果贵、多久跑一次、在哪里降级（写「都很轻」等于没写）

**门禁二**：焦点时刻必须来自这个产品与这个版面。通用淡入上浮、hover 上浮、视差层、逐屏滚动揭示都不是主张。

**权重按模式定**（见 4.2）：Operate / Read 压到 1–2，Persuade / Experience 可到 3–4。

### 2.3 等分：把界面切成 N 块 【定】

不画网格线。只是心里把版面**等分成 N 块**，后续所有宽度都用「第几块到第几块」描述。

**块是地基，不是栅栏。** 它只规定起止点能落在哪里，不规定谁必须站在哪里。

| 等分数 | 用在哪 |
|---|---|
| **6** 块（默认） | 大多数页面。粗细适中，容错高 |
| 4 块 | 极短、居中、单一主张 |
| 8 块 | 图文并置、卡片组 |
| 12 块 | 复杂对比、计量型界面 |

**一个界面只用一种等分**，不许 6 和 8 混用。混了，层级就散了。

### 2.4 空间主张：等分之后（门禁三）

等分定下块线，才能写得出「占第几块到第几块」。三行：

- **主次**：哪一块是主体，靠什么尺度与位置压住其他块
- **节奏**：疏与密各落在哪，哪一处是这页的呼吸点
- **落位**：主体占第几块到第几块，其余块如何借势

**门禁三**：三行里有一行答不出来，不许进入按块分配。凭手感摆完再补理由，等于没有主张。

### 2.5 按块分配 【定】

逐个元素写跨度，但**起点不固定**。

一个 6 等分的版面可以这样用：

| 元素 | 跨度 | 说明 |
|---|---|---|
| logo | 1 → 2 | 靠左，占地基的第一块 |
| 导航 | 5 → 6 | 靠右，与 logo 拉开 |
| 主标题 | 2 → 4 | 不从第 1 块起，左边留一块呼吸 |
| 副标题 | 2 → 5 | 比标题宽而不跨，形成阶梯 |
| 正文 | 2 → 5 | 与副标题同起点，读感连贯 |
| 按钮组 | 2 → 3 | 短促，收在左侧 |
| 元信息 | 2→2 / 3→4 / 5→6 | 三栏并置，靠右的一栏拉满 |

这只是**常用起止点**，不是模板。同一页的不同区块可以换起点：一个靠左、下一个靠右，只要起止点落在同一批分界线上。

**四条规矩**：

1. 跨度只用**整数块**，不出现 2.5 块
2. 同类内容的跨度要一致（两段并列正文不能一个占 4 块一个占 5 块）
3. 左右留白是**未占用的块自然形成**的，不另加 padding
4. **起点自由**：可以第 1 块起，也可以第 2 块起；可以靠左，也可以靠右

**规整感来自反复落在同一批位置上，不来自规定谁必须站哪。**

### 2.6 实现：用比例，不用画线 【定】

```css
.split {                 /* 六等分地基 */
  display: grid;
  grid-template-columns: repeat(6, 1fr);
  column-gap: 24px;
}
.split > .s24 { grid-column: 2 / 5; }   /* 第 2 块到第 4 块 */
.split > .s25 { grid-column: 2 / 6; }
.split > .s12 { grid-column: 1 / 3; }
```

跨度换算：占第 a 块到第 b 块 → `grid-column: a / b+1`。

不写任何辅助线、不引入网格工具。想目测校验，临时在 DevTools 里勾一下 grid 即可。

### 2.7 破格：服务阅读动线 【定】

**定义**：破格不是跨线，是在**视线跑得太快的地方加一处图案**，服务阅读。

**前提**：全页只有一个主体。破格图案只服务这一个主体。

#### 判据（按顺序问）

1. **这一屏的眼睛跑得快吗？** 信息密集的区块本身就在减速，不加。长页面不要求每屏都有。
2. **主体够重吗？** 主体重 → 加引导型；主体轻 → 加承重型。
3. **加完之后，视线是停住了，还是被送走了？** 答不上来就不加。

#### 两类图案，按视觉重量分工

| 角色 | 用什么 | 动效 |
|---|---|---|
| **暂停**（减速） | 实心块、实心圆、大面积色斑 | 静态，或极轻入场（100–150ms 淡入） |
| **引导**（送走视线） | 细线、箭头、序列、编号 | 中度：跟随滚动 / 跟随光标 / 自带循环（150–300ms，最长 500ms） |

实心重，眼睛会沉下去；线轻，眼睛会滑过去。选哪类看你要视线停还是走。

#### 约束

- **一屏最多一处。这是上限，不是配额**
- 破格图案属于**内容层**，不是控件层：不许玻璃、不许模糊、不许半透明渐变，只能实色。一旦变轻，重量就没了
- **只能乱它一个**。主体、正文、文字块仍全部落在块线上
- 破格图案动了，同屏其他元素不许动（与「一屏一个焦点时刻」同一条）

#### 承重图案的尺度（A 版参数）【定】

| 项 | 值 |
|---|---|
| 尺寸 | 留白面积的 **1/3 – 2/5**（按最短边计） |
| 与文字块间距 | ≥ 一个栏距（24px） |
| 边缘 | 可局部化开（渐变自 60–70% 处开始），但主体不可整体透明 |
| 交互 | **无**。无 hover、无点击、无指针变化 |

小到留白的 1/4 以下就失去承重，变成标点；大到 1/2 以上会压住正文，欺负阅读。

#### 图案从哪来（降级链）【定】

**本技能不生成图案。** 只负责把形落到版面上。

1. **纯 CSS / SVG 自绘** —— 圆、方、线、点阵、渐变遮罩。**优先**，无依赖、可调、体积为零
2. **当前环境配了生图能力** —— 生成后取回，按上面尺度裁切、调透明度、做融入。不合格（重量不对、边缘碎、带文字）就重生成，不硬用
3. **没配，或生成不合格** —— 找可商用几何 / 抽象素材，同样按尺度改
4. **都没有** —— 用最朴素的形：一个实心圆或一个方块。极简里朴素形常常比精修素材更对

不为了填版面而硬塞素材。

> 规则只写「条件 + 动作」，不绑定具体供应商或模型。换服务不用改本文件。

#### 素材版权（硬限制）【定】

**只允许两类授权**：

- 可商用（公有领域、CC0、或明确标注可商用）
- 无需署名，或不依赖具体作者人格

**只允许两类形态**：

- 几何形（圆、方、线、网格、点阵）
- 抽象纹理（噪点、渐变、材质）

**禁止**：插画、摄影、人物、场景、需署名的作品、来源不明的图、带水印或文字的图。

理由：破格图案是**无名之形**，服务动线，不表达内容。用上插画或照片，它就从「承重的形」变成「有主题的图」，与「一页一个主体」直接冲突。

#### 反例

- 为了设计感随机错位、每个区块都偏移一点
- 一屏两处破格
- 破格图案只是个装饰贴图，不承担动线职责
- 信息密集的区块里再塞图案，把视线搞乱

**门禁四**：每一处破格都要能回答「它把视线停在哪，或送到哪」。答不上就退回块内。

## 3. 控件与内容分离 【定】

来自 Liquid Glass 的行为规则，材质本身不搬，行为规则搬。

### 3.1 层结构

页面只有两层：

| 层 | 装什么 | 允许的视觉手段 |
|---|---|---|
| **控件层** | 导航、标签栏、浮动按钮、浮层、工具条 | 半透明、模糊、描边、浮起阴影 |
| **内容层** | 正文、图片、卡片、列表、表格 | 纯色、纸纹、留白；**不加玻璃** |

**铁律**：模糊与半透明只允许出现在控件层。内容区永远干净——不许玻璃列表、玻璃卡片、玻璃表格单元格。

### 3.2 三条行为

- **控件浮在内容之上**，是独立功能层，不是内容的一部分
- **控件退让**：滚动时导航收缩、变淡、可隐藏；回滚时展开。不做常驻动画
- **底图亮时的暗化**：控件若浮在明亮图片上，加 35% 暗化层保证可读

### 3.3 特效预算

所有特效（模糊、阴影、渐变、纹理）加起来，**面积不超过画面 15%**。

## 4. 两种模式 【定】

同一套 token，两种驱动方式。

| | `page` 网页 | `slide` 幻灯片 |
|---|---|---|
| 画布 | 流式，随视口伸缩 | 固定 1280×720，等比缩放 |
| 动效触发 | 滚动进入视口 | 翻页时入场 |
| 字号基准 | 16px | ×1.4 倍率 【默认】 |
| 导航 | 滚动 + 锚点 | ← → 翻页、键盘、进度 |
| 溢出 | 页面变长 | 必须一屏装下 |
| 导出 | 不需要 | 打印成 PDF，`@page` 横向 |

**硬约束**：`slide` 模式禁用一切滚动触发组件。`FadeContent`、`ScrollReveal`、`ScrollFloat`、`ScrollVelocity` 在幻灯片里不会触发，改用翻页驱动。

### 4.2 四种访客模式 【定】

交付形态（`page` / `slide`）是第一条轴，**访客的成功长什么样**是第二条轴。两条叠加使用。

| 模式 | 访客的目标 | 我们的页 | 动效权重 | 破格密度 |
|---|---|---|---|---|
| **Persuade 说服** | 决定并行动 | 落地页、定价页、活动页 | 可承载声音：允许一个完整序列 | 可有一处承重 |
| **Operate 操作** | 完成一个任务 | 工具界面、后台、设置 | 只服务反馈与状态，快而少 | 不加 |
| **Read 阅读** | 看懂一件事 | 文档、文章、说明页 | 只解释结构，不做编排 | 不加 |
| **Experience 体验** | 进入作品本身 | 作品集、作品展示页 | 可承载声音：首屏即作品 | 可有一处，且服务主体 |

**判据按页面算，不按产品算。**工具产品的落地页仍是 Persuade；设计工作室的文档页仍是 Read。

**后果**：动效强度不再是全站 2/10 一刀切。Operate / Read 压到 1–2，Persuade / Experience 可到 3–4，但 7.3 的「一个焦点时刻」在任何模式下不变。

## 5. 配色

### 5.1 纲领 【定】

**不锁色值，锁原则。** 风格标签（木色极简、意式极简）只定气质，不预设 hex。

色值来自 `frontend-assets` 仓库，技能只引用，不内置。

### 5.2 五条硬规则 【定】

1. 单画面 **≤5 色**
2. 每个画面有**一个明确主色**（主色可以是中性色本身）
3. 对比**克制**，不出现高对比
4. 留白充足（见 6.3）
5. 用亮色时总色数 **≤3**，且亮色只承担三种职能之一：强调功能 / 突出主体 / 凸显个性

### 5.3 多色的唯一合法理由 【定】

同系列不同产品之间做区分。除此之外，多色就是失控。

### 5.4 底子 【参考，不强制】

三组方向，从库里挑，不钉死：

| 方向 | 库里对应 |
|---|---|
| 灰系中性（暖灰 / 冷灰 / 石灰色 / 灰褐） | `stone` `neutral` `zinc` `gray` `slate` |
| 米色与大地（米白 / 燕麦 / 沙色 / 浅咖 / 灰褐） | `ivory` `oat` `sand` `clay` `taupe` |
| 黑白灰 | `neutral` 两端 |

### 5.5 可测阈值 【默认】

- 中性色饱和度：HSL **S ≤ 45%**
- 主色与底色明度差（Lab ΔL）：**20–35**；超过 50 算高对比，不合规

### 5.6 亮色 【定】

- 只做强调、主体、个性三件事之一
- 单画面最多 1 个亮色色相，最多用它的 2 个档
- 大面积色块不得用亮色，亮色面积 **≤8%** 画面

### 5.7 对比与取色硬指标 【定】

定性说「对比克制」不够，下面三条是可测的：

1. **正文与占位文字对比度 ≥4.5:1**，大字（≥24px 或 ≥19px 粗体）**≥3:1**
2. **彩色底上的次级文字，从该色相里调色，不得直接用灰**。灰在彩色上会脏，也会把层次搅成三层
3. 深浅由**使用场景**决定：谁在看、在哪、什么环境光。不按品类选（「工具类习惯用深色」不是理由）

**验收**：DevTools 取色器看对比度数字；截图后用吸管取三个点，看次级文字是不是从底色相里出来的。

## 6. 字体 / 间距 / 版面

### 6.1 字体策略 【定】

**分两种交付，两套字体来源，不混用。**

| 模式 | 用在哪 | 字体从哪来 |
|---|---|---|
| **本地模式**（默认） | 自己机器上看、截图、录屏、内部演示 | 本机已装的私有字体，栈里只写名字，不打包任何文件 |
| **网页模式** | 对外发布、打包给别人打开、挂服务器 | 只准 OFL 可再分发字体，打包 woff2 子集 |

本地模式零文件：装了就用，没装回落系统字体。网页模式必须有文件，因为别人的机器上没有 MiSans。

**四条硬限制：**

1. MiSans、HarmonyOS Sans 明文禁止「单独再分发」与「修改」，子集化在法律上算修改 → **这两种字体只准本地用，任何对外交付的包里不许出现**
2. 网页模式只准 OFL 1.1 字体（Noto 系列、LXGW WenKai、Sarasa Mono）：可再分发、可子集化、可商用
3. 中文单字重全量 3–10MB，网页模式必须按实际用字子集化
4. 导出 PDF / 卡片 CSP 会拦外链字体，导出场景一律按本地模式处理

**后果**：本地模式按「装了字体的效果」验收；网页模式必须**两遍都验**——子集文件加载成功，以及子集缺失时回落不塌。

### 6.1.1 两套字体栈 【定】

**本地模式的四款私有字体**（`skill/fonts.json`，文件在 `F:\OH-WorkSpace\fonts-src\`）：

| 字体 | 角色 | 许可 |
|---|---|---|
| MiSans | 正文（中文主用） | 免费商用，禁再分发 / 禁改编 |
| HarmonyOS Sans SC | 正文（备选） | 免费商用，禁再分发 / 禁修改 |
| Montserrat | 展示字（拉丁） | SIL OFL 1.1，可再分发 |
| DejaVu Sans Mono Nerd Font | 等宽 | Bitstream Vera，可再分发 |

**网页模式的四款 OFL 子集**（`fonts/fonts.css`，六个 woff2）：

| 字体 | 角色 | 字重 | 体积 |
|---|---|---|---|
| Noto Sans SC Web | 正文 | 400 / 500 | 315 / 318 KB |
| Noto Serif SC Web | 标题 | 400 / 600 | 410 / 418 KB |
| LXGW WenKai Web | 引文 | 400 | 399 KB |
| Sarasa Mono SC Web | 等宽 | 400 | 364 KB |

```css
/* 本地模式（默认）：只写名字，不打包文件 */
--font-display: "Montserrat", "MiSans", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
--font-body:    "MiSans", "HarmonyOS Sans SC", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", system-ui, sans-serif;
--font-mono:    "DejaVuSansM Nerd Font Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace;
--font-kai:     "LXGW WenKai", "Kaiti SC", "KaiTi", "STKaiti", serif;
```

```css
/* 网页模式：<html data-fonts="web"> + 引入 fonts/fonts.css */
--font-display: "Noto Serif SC Web", "Noto Serif SC", "Songti SC", serif;
--font-body:    "Noto Sans SC Web", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
--font-mono:    "Sarasa Mono SC Web", "DejaVuSansM Nerd Font Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace;
```

切换只动一个属性：`<html data-fonts="web">`。`tokens.css` 里两套栈都写好了，不加属性就是本地模式。

分工：展示字拉丁用 Montserrat（本地）/ Noto Serif SC（网页）；正文中文 MiSans 主用、鸿蒙备选（本地）/ Noto Sans SC（网页）；数字与代码用 DejaVu Mono（本地）/ Sarasa Mono（网页）。

**建议只装这几个字重**，其余用不上还拖慢字体列表：

- MiSans：Regular / Medium / Semibold
- HarmonyOS Sans SC：Regular / Medium
- Montserrat：Regular / Medium / SemiBold
- DejaVu Mono：Regular / Bold

### 6.1.2 四个角色的分工 【定】

| 变量 | 管什么 | 用在 |
|---|---|---|
| `--font-body` | 正文 | 段落、列表、界面文字 |
| `--font-display` | 标题 | h1 / h2 / 幻灯片章节页 |
| `--font-kai` | 引文、叙事 | 引言、项目背景叙述、一段内的强调 |
| `--font-mono` | 等宽 | 数字、代码、表格对齐 |

**楷体的使用限制**：楷体抓眼，用多了整站会偏文艺，和极简是对冲的。

- 只用于**引文与项目叙事**，不当正文、不当标题
- 一个页面**最多一处**
- 每处**不超过一段**（约 3 行）
- 楷体段落用左侧细线或小幅内缩与正文区分，不加背景色

### 6.1.3 禁用清单 【定】

- ❌ 对外交付的包里出现 MiSans / HarmonyOS Sans 的任何形式，含 woff2 子集
- ❌ 打包苹方、微软雅黑的字体文件
- ❌ 打包或子集化商业字体（Google Sans、Myriad Pro、Eras、Avant Garde、Neo Sans Pro、Sackers Gothic、DIN 1451）
- ❌ 网页模式用 `@font-face` 指向未确认授权的字体文件
- ✅ 本地模式在 `font-family` 栈里写字体名做回落——不复制、不传播，风险最低
- ✅ 网页模式只用 OFL 字体，子集自己生成

### 6.1.4 字重 【定】

只用 **400 / 500**，中文没有 350 / 450 这种中间值。

深底浅字时：字重 400，靠行高 1.8 + 字距 +0.012em 补偿；若仍发虚，直接跳 500，不要停在中间。

层级靠字号、颜色、间距，不靠加粗。不用 Inter 当默认。

### 6.1.5 展示字体必须自托管 【定】

来自 impeccable craft floor 的硬规则，与上一节并行：

> 决定一页声音的展示字体，不许拿「本机最近的那个」当回落。最近的字体是失败，不是回落。

落到我们的两套栈上：

- **网页模式**：展示字体必须是交付包里的 woff2（目前是 Noto Serif SC Web）。别人打开看到的就是定稿的字，不是苹方
- **本地模式**：可用 MiSans，但只在「这个展示字本来就想用 MiSans」时成立；不想用就装对应的开源字体，不许靠回落凑
- **系统字体当展示字一律不许**（Impact、Arial Black、平台默认宋体/sans）。它没有性格，也说明你没做决定

**例外**：正文与界面文字的回落仍然允许（见 6.1 的两套栈）。这条只管**展示字**——标题、首屏大字号那句。

### 6.2 字号与阅读度量 【定】

三档体系，按信息密度调用，共用一套底层刻度：

| 档 | 阶梯（rem） | 用在 |
|---|---|---|
| **A 精简三档** | 1.75 / 1.25 / 1.0 | 落地页、单一信息页、幻灯片封面 |
| **B 四档带过渡**（默认） | 1.75 / 1.5 / 1.25 / 1.0 | 项目详情、作品集内页、长文档、幻灯片内容页 |
| **C 苹果式双档** | 2.125 / 1.0625 | 幻灯片章节页、数据大字、全屏主张 |

- **一屏只用一套**，不许混搭
- 正文不小于 16px（C 档 17px）
- **行宽**：中文 `--measure: 32–36em`（≈32–36 字/行）；拉丁 65–75ch 最佳，低于 60 或高于 80 重排
- **字距下限**：`letter-spacing` 不得低于 −0.04em；−0.02 到 −0.03 通常更好看
- **展示字上限**：display 字号 ≤6rem；再大要么改版心，要么改字号档
- 元信息固定 0.8125rem（13px），不参与档位变化
- 行高随行宽反向调；深底浅字三轴补偿
- 幻灯片：封面 A / 章节页 C / 内容页 B

完整取值、行高与检查清单见 `skill/typography.md`，可直接引用的变量在 `skill/tokens.css`。

### 6.3 留白 【定】

不用百分比。用**比值**：

- **区块之间的留白 ≥ 区块内部间距的 4 倍**（例：区块间距 96px，卡片内边距 24px）
- 幻灯片：页边距 ≥ 内容间距的 **3 倍**
- 段落之间用间距或首行缩进二者之一，不同时用

### 6.4 间距阶梯 【定】

**4 为基单位**：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96`

| 用途 | 值 |
|---|---|
| 版心 | 780–820px |
| 正文内边距（桌面） | 40–54px |
| 幻灯片安全边距 | 64px 【默认】 |

分组靠邻近，不靠加容器；节奏来自 tight 与 generous 的对比，不要一个值铺满全页。

### 6.5 同心圆角 【定】

嵌套元素共享圆心，圆角随层级递减：

| 层级 | 圆角 |
|---|---|
| 外层容器 / 大卡片 | **12–16px**（大卡片取 12，整屏容器取 16） |
| 内层区块 / 小卡片 | 8–12px |
| 控件 / 按钮 | 6px；小标签、状态点可用胶囊 |

**禁止全站一个圆角值。** 另：`1px 边框 + 大软阴影`同时上叫幽灵卡片，只选一个（见 9 节）。

### 6.6 版面结构 【定】

- **眯眼测试**：虚化细节后仍能分出主、次、组，否则层级失败
- 禁止三栏等高功能卡
- 重复的卡片 / 分栏必须真的等价，否则是框架默认
- 响应式是**结构性重排**，不是等比缩小
- 触控目标可用，即使视觉标记很小

### 6.7 重排的三种手法 【定】

窄屏不是把六块等比例缩小，而是**改块的关系**。只用三种手法：

| 手法 | 什么时候 | 怎么做 |
|---|---|---|
| **叠** | 若干块是并置关系（三栏功能、双图并排） | 横向 span 改纵向单栏，跨度全部落回满宽 |
| **换轴** | 图形与文字的关系决定理解 | 上图下文，或图转背景、文字浮上；不把图缩成缩略图 |
| **降级** | 这一块在窄屏不承载主张 | 删、折进折叠区，或换成一句话 + 链接。**不许把同一堆内容换个字号塞回来** |

**断点按内容定，不按设备定**：从窄往宽拉，哪里开始难看就在哪里断。常用 640 / 768 / 1024，超过三个就是没想清。

**硬指标**：320px 不横滚；移动端正文 ≥16px（低于 16 的输入框会被 iOS 强制缩放）；触屏禁用只靠 hover 的交互；触控目标 ≥44×44。

**连续性手段**：字号、间距、版心用 `clamp()` 做连续变化，断点只用来改结构。两种手段不要混在同一属性上。

## 7. 动效

### 7.1 时长表 【定】

| 时长 | 用途 |
|---|---|
| 100–150ms | 即时反馈（按下、hover） |
| 150–300ms | 常规状态切换 |
| 300–500ms | 布局、浮层、视图切换 |
| 500–800ms | 焦点入场 |

**出场比入场快。**

### 7.2 缓动 【定】

`cubic-bezier(0.16, 1, 0.3, 1)`，不反射性上 bounce / elastic。

### 7.3 节流 【定】

- **只给一个焦点时刻**
- **同屏同时只让一个东西动** 【默认：1 个序列】
- 不做常驻动画；只在状态变化时动
- 控件退让（滚动收缩）算状态变化，不算常驻动画

### 7.4 可感知下限 【定】

**动效存在的前提是能被看见。** 幅度低于下表任一通道的下限，等于没做——不能算「有这个动效」。

| 通道 | 下限 |
|---|---|
| 位移 | 可见位移 ≥8px，或 ≥视口短边的 0.5% |
| 透明度 | 起止跨 ≥0.3，且不得只动一段浅淡区间 |
| 尺度 | 面积变化 ≥4% |
| 明度 | ΔL ≥8 |

四条附加约束：

1. 时长 ≥400ms，≤800ms（落在焦点入场档）
2. 触发点在元素进入视口**中部**之后（`IntersectionObserver` threshold ≥0.2，或 `rootMargin` 收进 −10%），不许在页面加载时点火
3. 一个序列只播一次，不重复入场
4. 作用对象不得小于三行文字的高度；只动几个字、一个数字，视为不合格

**反例**：六个字的 8px 淡入、加载即触发且只触发一次、只动单个数字、动效播在用户看不到的折叠区外。

**但达标不等于合格。** 即使幅度、时长、触发全部合规，一个通用淡入上浮、hover 上浮、视差层或逐屏滚动揭示，仍不算这一页的动效。它只是填补空白的默认动作。

**判断句**：拿掉这个动画，页面会丢掉一个意思吗？只丢掉一点装饰，就不该有。

**验收**：DevTools Animations 面板逐帧过一遍，或用 0.25× 录屏看一遍；看不出来就是不合格。

### 7.5 强度 【默认】

`MOTION_INTENSITY = 2/10`。`taste-skill` 基线是 6，对极简是对冲的，必须覆盖。

### 7.6 技术约束 【定】

- 默认状态内容必须可见，脚本挂了不能白屏
- 不动 `width / height / top / left / margin`，用 transform 或 FLIP
- 模糊、滤镜、阴影、canvas、shader 限制在局部
- `will-change` 只在动画期间加
- `prefers-reduced-motion` 留替代路径：减少位移，保留状态变化，不是全关

### 7.7 按语义选材质 【定】

`transform` 与 `opacity` 是地基，不是全部家当。选什么，取决于这段过渡要**说清楚什么**：

| 要传达 | 用什么 |
|---|---|
| 连续性与关系 | 共享元素、FLIP、视图过渡、有方向的空间位移 |
| 焦点与深度 | 受控的 blur、filter、backdrop、光与影的变化 |
| 揭示与构图 | mask、clip-path、裁切、受控遮挡 |
| 材质与能量 | 颜色、渐变位移、纹理、扭曲（限局部，且世界观支持时） |
| 状态与反馈 | 能让人一眼看懂因果的最小变化 |

**一条强材质思路贯穿焦点序列，比堆五种技巧强。** 为了好看叠技术，是最典型的动画负债。

同级列表同时入场时，允许错开（stagger），但**总延迟要封顶**（≤200ms），且不得把每一个滚动到的区块都重新解释成错开列表。

## 9. 浏览器表面 【定】

你没画的那部分，也在替你说话。这些东西默认值全属于浏览器，而不属于任何设计系统，所以它们是最便宜的「这页是被建造的，还是被拼装的」信号，也是模型最容易漏的一组。

| 表面 | 要做什么 |
|---|---|
| 文字选区 `::selection` | 用主色低饱和版，不用默认蓝 |
| 光标 `caret-color` | 跟随主色 |
| 滚动条 | 细、无轨道底色；深色页要单独给一套 |
| 焦点环 `:focus-visible` | 必须有，且用主色；不许 `outline: none` 了事 |
| 下划线偏移 | `text-underline-offset` ≥2px，`text-decoration-thickness` 可调 |
| 表格与统计数字 | `font-variant-numeric: tabular-nums`，数字竖着对得齐 |
| 禁用态 | 降不透明度而不是换成灰字 |
| 打印 | 至少可读：去背景色、保黑字、链接补 URL |

**验收**：选中一段正文、Tab 走一遍、看一遍长表格里两行数字、切一次禁用元素。四项里有一项是浏览器默认，就不算完工。

## 10. 反例清单

出现任何一条，视为不合格：

- AI 紫渐变、深色 mesh 居中的 hero
- 三张一模一样的功能卡横排
- **玻璃拟态用在内容上**（玻璃卡片、玻璃列表、玻璃表格）
- 每屏都做滚动揭示、无休止微动效
- Inter + slate-900 组合
- 渐变按钮、重阴影（超过 `rgba(0,0,0,.04)`）
- 纯黑 `#000` / 纯白 `#fff` 大面积使用
- 多个强调色同时出现
- 字重 >500、边框 >2px
- 冷灰文字 `#666` `#888` `#999`
- 假名字（John Doe）、Lucide 用户图标当头像
- 每段都加图标、每个区块都套卡片
- 全站一个圆角值
- 用彩纸、粒子、弹跳制造「愉悦」
- 为了好看牺牲可读性（Responsibility 违背）
- **标题上方的 eyebrow / kicker 小字**（硬禁，没有 brief 能换回来；标题自己承担重量）
- 章节序号 01 / 02 / 03——除非序号本身携带读者需要的信息
- hero 数字模板：大数字 + 小标签 + 一排辅助指标 + 一个强调色
- 同尺寸「图标 + 标题 + 正文」卡片堆成页面结构；嵌套卡片永远错
- 渐变文字（强调靠字重与字号，不靠渐变）
- 硬偏移阴影（`4px 4px 0`）——除非整个世界观是 neo-brutalism
- 等宽字体当「技术感」布景（只允许代码、数据、度量）
- emoji 或 Unicode 符号冒充图标系统（图标要么来自库，要么自己画，笔画粗细统一）
- 几何遮罩冒充抠图（圆、多边形、径向渐变硬切图边缘，比不做更难看）
- 亮色 / 暗色按品类选（要按使用场景选）
- 声明层级时同时上边框和阴影
- 用 `box-shadow` 零偏移彩色光晕冒充层次

## 11. 与现有技能的关系 【定】

| 技能 | 提供什么 | 本技能怎么用 |
|---|---|---|
| `impeccable` 4.8.0 | 验收标准、反例清单、动效主张、四模式 | 验收层全文吸收；它的工作流命令（`shape` `init` `critique` `polish` `live`）不搬 |
| `design-taste-frontend` | 数值：色彩、字号档位 | 继承字号与间距体系 |
| `taste-skill` | 判断：三档 dial、禁止模式 | 继承反例清单，覆盖两个旋钮默认值 |

**三者与本技能冲突时，以本技能为准。**但本技能与 `impeccable` 的验收标准冲突时，以 `impeccable` 的**硬禁与可测值**为准，以本技能的**极简取向**为准——前者管「不许什么」，后者管「要往哪走」。

完整细则见 `skill/craft-floor.md`（品质底线与硬禁）与 `skill/checklists.md`（a11y / 边界 / 响应式 / 性能阈值）。
